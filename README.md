# SBS Lab

Минималистичная веб-платформа для SBS-разметки TTS: сравнение двух аудио, бинарные аудио-вопросы, роли администратора и разметчика. Текущая версия — интерактивный frontend-MVP: работает без сервера и сохраняет проект в `localStorage`.

## Возможности

- попарное A/B-сравнение с вариантом «равноценны»;
- вопросы «да / нет / не уверен»;
- быстрые клавиши `1`, `2`, `0`, `←`, `→`;
- автосохранение, карта прогресса, переход назад и вперёд;
- импорт заданий и экспорт результатов в JSON;
- кабинет администратора с быстрым созданием заданий и загрузкой аудио;
- демо-пользователи, управление активностью и отдельный кабинет разметчика;
- регулируемое перекрытие `1–7` и автоматическое назначение наименее загруженных людей;
- закрытие задания после нужного количества уникальных ответов;
- консенсус по большинству голосов и agreement каждого разметчика с большинством остальных;
- адаптивный интерфейс для ноутбука и телефона;
- расширяемая TypeScript-модель заданий.

## Роли и перекрытие

Справа сверху находится демо-переключатель аккаунтов. Администратор видит задания, команду, статистику и настройки; разметчик — только назначенную ему очередь и личный прогресс.

При перекрытии `3` задание назначается ровно трём активным разметчикам. Четвёртый его не увидит. После трёх уникальных ответов задача закрывается, а итогом становится самый частый ответ. Если лидеры набрали одинаковое число голосов, результат помечается как спорный.

Agreement считается аккуратнее: для каждого ответа пользователя берётся большинство **остальных** ответивших. Собственный голос не участвует в определении эталона; случаи без большинства пропускаются.

> Ограничение MVP: защита от одновременного захвата слота несколькими браузерами требует серверной транзакции. Интерфейс и модель назначения уже готовы, но перед командным production-использованием нужно подключить backend, базу и настоящую авторизацию.

## Запуск

```bash
npm install
npm run generate:audio
npm run dev
```

Сборка для публикации:

```bash
npm run build
npm run preview
```

## Формат датасета

Готовый пример лежит в [`public/tasks.example.json`](public/tasks.example.json). В интерфейсе нажмите `···` → «Импорт задач» и выберите JSON.

```json
{
  "project": "Эксперимент #42",
  "defaultOverlap": 3,
  "tasks": [
    {
      "id": "sbs-001",
      "type": "pairwise",
      "text": "Текст для озвучивания",
      "question": "Какой вариант звучит естественнее?",
      "requiredAnnotations": 3,
      "audioA": { "src": "/audio/a.wav", "label": "Model A" },
      "audioB": { "src": "/audio/b.wav", "label": "Model B" }
    },
    {
      "id": "intonation-001",
      "type": "boolean",
      "text": "Это вопрос?",
      "question": "Есть ли вопросительная интонация?",
      "requiredAnnotations": 3,
      "audio": { "src": "/audio/question.wav", "label": "Model A" }
    }
  ]
}
```

`src` может быть абсолютным URL или путём к файлу на том же хосте. Если `requiredAnnotations` отсутствует, используется `defaultOverlap`. Назначения генерируются автоматически при импорте. Для нового типа задания добавьте TypeScript-тип в `src/types.ts` и отдельный renderer в `src/components`.

## Следующий production-шаг

Frontend уже разделяет сущности `users`, `tasks`, `assigneeIds` и `annotations`. Для реальной команды их стоит перенести в Postgres/Supabase и выдавать следующее задание через атомарную серверную операцию. Это гарантирует, что при перекрытии `3` слот не получит четвёртый пользователь даже при одновременной работе.
